# SM120 Oja backward resource failure

The unchanged BF16 Oja2 test `test_chunk[B2-T1000-H3-K128-M128-scale0.1-torch.bfloat16-qnTrue-knTrue-h0True-htTrue]` fails in the original `chunk_oja_bwd_kernel_dhu_blockdim64`: required shared memory 425984 bytes, available 101376 bytes. The failure reproduces in a fresh frozen upstream process (`baseline-oja2-resource-20261113.log`), independently of the triangular-solve change. The shared recovery stops on this failure; it is not a completed gate.

Although q/k are BF16, the original test supplies FP32 v; the backward vg tensor is also FP32. No dtype was changed by this investigation. The existing pruner retains only pipelined configurations for V=128, while its single-stage branch handles FP32 V>128. A diagnostic that retains the already-declared single-stage candidates passes the complete original failing test, including outputs, final state and all seven gradients, with unchanged tolerances. It selects BK16, four warps, one stage. See `oja2-single-stage-diagnostic.json/.log/.xml`.

The independent fix `b6172a05f2405a73c96ec190ee41f4083faa31a8`, based on current main `0a649e4c7201f0edcba734832773fe8ab371367a`, retains the existing single-stage candidates on SM120. The prior restriction for larger FP32 states remains. Kernel bodies, arithmetic, tensor precision, storage, interfaces and test parameters remain unchanged. This is a hardware-wide candidate policy, not a benchmark-case dispatch. Other architectures retain their candidate policy.

Only Oja and Oja2 call this backward-state helper. Other functions in the same file, imported by GSA2 and related modules, are unchanged. Import-based dependency discovery is not treated as proof that those paths invoke this pruner. The Oja and Oja2 original files are byte-identical between frozen and current main.

Triton 3.5.1 applies the early pruner before constructing its disk tuning-cache key and hashes the resulting candidate list. Retaining the single-stage candidates therefore changes that key naturally; no cache deletion or production cache disabling is needed. Formal source validation uses the default `FLA_CACHE_RESULTS=1`; the preceding diagnostic disables only disk tuning-result reuse and is not the final source gate.

Environment: RTX 5070 Ti Laptop, SM120, PyTorch 2.9.1+cu128 / Triton 3.5.1. Strict IEEE dot settings and cuBLAS TF32 override disabled. The diagnostic has one unrelated pytest warning about an already-imported anyio module; its numerical assertions pass normally.

Final standalone validation passes all 57 original Oja/Oja2 kernel cases (24 + 33), with the original inputs, references, tolerances and skips unchanged. The four pure-PyTorch reference cases pass separately on A800. The final combined ReWY integration passes 235 cases with 50 existing skips. Complete commands, source hashes and scheduling-cost ABBA samples are linked from README.md. The initial timing harness failed before collecting samples because of stream/capture synchronization; its log is preserved, and the corrected harness uses a complete fresh ABBA sequence. This is a compatibility fix, not a new algebraic optimization or a datacenter performance claim.
